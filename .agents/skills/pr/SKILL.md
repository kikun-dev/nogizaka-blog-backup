# PR 作成

1. ブランチと `main` の差分を確認し、PR が 1 Issue の変更だけを含むことを確かめる。ユーザー由来の未コミット変更を勝手に含めない。
2. Issue の完了条件を一つずつ照合する。未達があれば修正し、判断が必要ならユーザーに確認する。未検証を達成済みと書かない。
3. 変更に応じて `pnpm test`、`pnpm lint`、`pnpm build` と必要な手動確認を行う。実行できなかった項目は理由を記録する。
4. `.github/PULL_REQUEST_TEMPLATE.md` に沿い、`Closes #<Issue番号>`、完了条件の証拠、影響範囲、テスト結果を日本語で書く。
5. ブランチを push して PR を作成し、ユーザーにレビューを依頼する。レビューを受け、指摘に対応し、再検証するまでマージしない。次の機能 Issue にも進まない。

PR 作成はマージの承認ではない。ユーザーが GitHub の PR 作成者本人で承認レビューを送れない場合は、PR コメントまたは会話でのレビューを受け、結果を PR に残す。
