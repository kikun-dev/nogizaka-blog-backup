# 坂道ブログ保存ツール

乃木坂46・櫻坂46・日向坂46の公式ブログを保存するツールです。現在は Web アプリのローカル実装を進めています。Web 画面でグループ、メンバー、保存内容、取得範囲を選べます。メンバー欄には期別ブログ、運営スタッフ、ポカも含まれます。写真は最大20件のブログから取得し、画面での長押し保存とZIP保存ができます。ブログ1件は既存 CLI で PDF と MHTML に保存できます。複数件のブログ保存と全件バックアップは今後の実装です。

## 必要な環境

- Node.js 24
- npm（Node.js 24 に付属する版）
- Playwright Chromium

## セットアップ

```bash
npm install
npx playwright install chromium
```

`.env.example` を参考に `.env.local` を作成し、`LOCAL_ACCESS_TOKEN` に推測されにくいランダムな値を設定してください。例: `openssl rand -hex 32`。この値は Git に登録せず、ブラウザの「ローカルアクセストークン」欄に入力します。

## ローカル Web アプリ

```bash
npm run dev
```

PC のブラウザで `http://localhost:3000` を開きます。アクセストークンを入力するとメンバー一覧が自動で読み込まれます。グループ→メンバー→「写真のみ」または「ブログ」→「最新1件」「最新N件」「ブログを選ぶ」の順に指定します。全件バックアップは別の入口から条件を確認します。写真のみは最大20件、ブログ保存は最大10件まで選べ、ブログ選択画面ではページを移動しても選択が残ります。この上限は画面とサーバーの両方で確認し、選んだブログは指定メンバーの公式一覧とも照合します。

「写真のみ」では「最新1件」「最新N件」「ブログを選ぶ」で条件を確認し、「写真を取得」を押します。押すと写真の結果画面へ切り替わり、取得中の状態と完了後の写真を同じ画面で確認できます。「条件設定に戻る」で選択を保ったまま戻り、「写真の取得結果を見る」で再表示できます。取得後はブログごとに写真が縦に表示され、個別保存とZIP保存ができます。写真0枚のブログと、写真の一部を取得できなかったブログは、その場に状態を表示します。写真モードではPDF/MHTMLを生成しません。

「ブログ」→「最新1件」または「ブログを選ぶ」で1件を選び、条件確認後に「この1件を保存」を押すと `.local-data/archive/<jobId>/` に保存します。条件確認後は、対象ブログのタイトルと公式一覧に掲載された日時を表示します。ブログ複数件と全件バックアップは今後の実行機能につなぐための設定画面です。選択一覧は公式サイトの一覧ページを読み、5分間だけサーバー内でキャッシュします。ブログ本文を個別に開くのは取得・保存を開始したときです。公式一覧にないブログは個別ページの URL を直接入力できます。

ジョブ状態は `.local-data/jobs/` に記録します。保存ファイルは `.local-data/archive/<jobId>/` に置きます。写真モードの画像と `photos.zip` もジョブ単位のフォルダに保存します。両フォルダは Git の管理対象外です。保存先を変えたい場合は `.env.local` へ `LOCAL_ARCHIVE_ROOT` を設定します。同時に実行する取得処理は1件、待機は最大10件です。サーバー再起動時に未完了だったジョブは、次の API アクセス時に失敗状態へ変更されます。

スマホで画面を確認する場合は、開発 PC とスマホを同じネットワークに接続し、スマホから `http://<開発PCのLAN内IPアドレス>:3000` を開いて同じアクセストークンを入力します。PC のファイアウォールが接続を遮断する場合は、ローカルネットワークからポート 3000 へのアクセスを許可してください。

### iPhone・iPadで写真を保存する

1. iPhone・iPadと開発PCを同じWi-Fiに接続し、Safariで `http://<開発PCのLAN内IPアドレス>:3000` を開きます。
2. `.env.local` の `LOCAL_ACCESS_TOKEN` と同じ値を画面に入力します。
3. グループ、メンバー、「写真のみ」、「最新1件」を選んで「この条件を確認」→「写真を取得」を押します。
4. 「取得した写真」に表示された写真を長押しし、Safariのメニューから「写真に保存」を選びます。写真アプリで保存結果を確認します。

### Androidで写真を保存する

1. Android端末と開発PCを同じWi-Fiに接続し、Chromeで `http://<開発PCのLAN内IPアドレス>:3000` を開きます。
2. `.env.local` の `LOCAL_ACCESS_TOKEN` と同じ値を画面に入力します。
3. グループ、メンバー、「写真のみ」、「最新1件」を選んで「この条件を確認」→「写真を取得」を押します。
4. 「取得した写真」に表示された写真を長押しし、Chromeのメニューから「画像をダウンロード」を選びます。ダウンロード先で保存結果を確認します。

ZIPを使う場合は「写真をZIPで保存」を押します。iPhone・iPadではZIPは通常「ファイル」アプリに保存され、写真アプリへ直接入りません。写真アプリへ保存したい場合は、画面に表示された写真を個別に長押ししてください。

## 既存 CLI

Web 化の間も従来の CLI を使用できます。

```bash
npm run archive -- \
  --url 'https://www.nogizaka46.com/s/n46/diary/detail/ブログID' \
  --output '~/Documents/SakamichiBlogArchive' \
  --limit 1
```

開始 URL からグループを自動判定します。投稿主体別の一覧ではなく、ブログの個別 URL を指定してください。主なオプションは `--limit 3`、`--delay 5000`、`--headed`、`--force` です。期別ブログやポカなども投稿主体別のフォルダに保存します。既存の `index.json` にある `memberName` は読み込み時に `authorName` として扱い、次の保存時に新形式へ移します。

## 共通取得エンジン

CLI は `lib/archive/index.mjs` の `archiveArticles()` を呼びます。同じモジュールの `inspectArticle()` はブログのタイトル・投稿主体・投稿日などを保存前に取得でき、Web サーバーからは `server/archive-engine.ts` 経由で両関数を呼べます。ブログ情報の確認では画像の読込状態をその時点の値として返し、PDF/MHTML 保存では従来どおり画像の読み込みを再試行します。

`lib/archive/` は、グループと URL、ブログ取得・メタデータ・画像、PDF/MHTML 生成、投稿主体別の索引・ファイル保存をモジュールごとに分けています。
